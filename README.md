# Portfolio — Flutter

A three-page responsive portfolio site: Home, About, Work.

## Running it

This bundle contains only `lib/`, `assets/` and `pubspec.yaml` — the platform
folders are generated by Flutter, so create them once:

```bash
flutter create --platforms web,android --project-name portfolio .
flutter pub get
flutter run -d chrome
```

Run that from inside this folder. `flutter create` will not overwrite the
`lib/`, `assets/` or `pubspec.yaml` already here.

To build the version you submit:

```bash
flutter build web --release
```

The output lands in `build/web/`. Push that to a `gh-pages` branch, or point
GitHub Pages at it, and paste the resulting URL into the WebLink column.


## Responsive behaviour

| Width | Layout |
| --- | --- |
| ≥ 1120 px | Permanent vertical nav rail on the left, name set sideways; hero splits into two columns |
| 760–1119 px | Nav collapses to a top bar; hero still two columns down to 820 px of content width |
| < 760 px | Single column throughout, compact top bar, portrait above the headline, seals stack above project text |

Breakpoints live in `lib/core/layout.dart`. Sections measure the width actually
available to them via `LayoutBuilder` rather than reading the window size, so
the rail and the max-width cap are accounted for.

## Structure

```
lib/
  main.dart                 named routes + page transition
  core/
    layout.dart             breakpoints, gutters, url helper
    routes.dart             route names, shared by nav and router
  theme/
    palette.dart            colour tokens
    app_theme.dart          typeface roles, ThemeData
  data/
    profile.dart            all personal copy in one place
    projects.dart           project records
  widgets/
    seigaiha.dart           the CustomPainter
    site_scaffold.dart      nav rail, top bar, footer
    ui.dart                 rules, headings, chips, buttons, hanko, portrait
  pages/
    home_page.dart
    about_page.dart
    projects_page.dart
```

Navigation uses `onGenerateRoute` with `pushReplacementNamed`, so the route
stack stays flat and the browser address bar tracks the page. The transition is
a 300 ms crossfade with about 1% of vertical travel, skipped entirely when the
system asks for reduced motion.
